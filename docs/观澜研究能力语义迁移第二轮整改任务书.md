# 11. R6 — 严格因果 Replay

## 11.1 强制因果链

Replay 必须验证：

```text
Outcome
→ Prediction
→ Decision
→ Strategy Signal
→ Monitor Run
→ StrategyDefinitionVersion
→ ScreenRun
→ ExperienceVersion
```

任一链接缺失、版本不一致或 PIT 冲突，Replay 必须拒绝。

## 11.2 禁止固定置信度

删除类似以下逻辑：

```python
confidence = 0.50 + 0.05 * min(attribution_count, 4)
```

Confidence 必须来自有记录的评估方法，例如：

- 样本覆盖；
- 数据质量；
- 归因一致性；
- 独立证据数量；
- 校准模型；
- 专家确认。

无法计算时返回 `unknown`，不得产生装饰性数字。

## 11.3 版本修订

- Rule Error 才允许提出规则修订；
- Data Error 应修正数据质量或 Provenance；
- Execution Error 应修正执行/成交模型；
- Thesis Error 应产生 Thesis/Experience 候选修订；
- 新版本先进入 DRAFT，不得自动替代生产版本；
- 修订必须生成 Artifact 和 Provenance；
- 版本号由事务安全机制分配，禁止简单 `old + 1` 竞态。

## 11.4 DoD

- 无 Decision 关联的 Prediction 无法 Replay；
- 关联错误 Monitor/Strategy 时拒绝；
- Replay 输出明确 attribution、证据和修订目标；
- 新 Strategy/Experience 版本有 Artifact、Confirmation 和审计链；
- 重复 Replay 幂等。
