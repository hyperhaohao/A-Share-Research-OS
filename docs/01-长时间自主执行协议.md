# 01 - 长时间自主执行协议

本文件将本项目定义为：

> **持续执行型工程任务，而不是一次性问答任务。**

Claude / Coding Agent 必须持续：

```text
Implement
→ Build
→ Test
→ Verify
→ Fix
→ Update State
→ Git Checkpoint
→ Next Task
```

直到 `TASK.md` 的最终完成条件全部满足，或遇到无法自行解决的真实外部阻塞。

---

# 1. 规则优先级

发生冲突时：

```text
用户当前明确指令
↓
TASK.md
↓
AGENTS.md / CLAUDE.md
↓
PLAN.md / STATUS.md / ROADMAP.md
↓
实际项目架构和已有代码
↓
README / docs
```

`PLAN.md` 和 `STATUS.md` 不能降低 `TASK.md`。

---

# 2. 每次启动/恢复必须执行

在开始代码修改前：

```text
pwd
git status
git log --oneline -10
```

然后读取：

```text
TASK.md
AGENTS.md
CLAUDE.md
PLAN.md
STATUS.md
ROADMAP.md
README.md
```

再根据当前 Milestone 读取对应 docs。

必须检查实际代码、配置、模型、接口、测试和构建状态。

禁止仅根据文档假设功能已经完成。

---

# 3. 建立和维护执行计划

`PLAN.md` 是动态执行计划。

可以：

- 拆分 Phase；
- 调整顺序；
- 发现复用能力后缩短实现路径；
- 根据真实依赖调整子任务。

但不能：

- 删除 TASK 要求；
- 把必须项改成 optional；
- 把失败测试删除；
- 通过降低需求适配当前实现。

---

# 4. 持续执行循环

持续执行：

```text
Read TASK
↓
Read PLAN
↓
Read STATUS
↓
Select highest-priority unfinished work
↓
Inspect existing code
↓
Implement
↓
Build
↓
Unit Test
↓
Integration Test
↓
Functional / Live Verification
↓
Fix
↓
Re-run verification
↓
Update PLAN
↓
Update STATUS
↓
Update ROADMAP when milestone state changes
↓
Git Checkpoint
↓
Continue
```

不得完成一小段后主动停止。

---

# 5. 错误处理

## Build Failure

必须：

1. 读取完整错误；
2. 判断根因；
3. 修改；
4. 重新 Build；
5. 直到通过或确认真实外部阻塞。

## Test Failure

禁止：

```text
delete test
skip test
comment failing code
weaken assertion
```

必须判断：

```text
implementation bug
or
test bug
```

修复真正问题。

## Dependency Failure

主动检查：

- Python / Node / Runtime；
- package version；
- lockfile；
- SDK；
- environment；
- API compatibility；
- build tool；
- OS-specific issue。

合理可处理时自行解决。

## Third-party Failure

区分：

```text
implementation bug
network
permission
configuration
API change
rate limit
source unavailable
```

能通过代码 / fallback / retry 解决则继续。

---

# 6. 允许暂停的真实条件

只有以下情况允许停止请求用户：

### Missing secret / private information

例如：

- API Key；
- Password；
- private account；
- private certificate；
- production-only secret。

### User-only permission

例如：

- 第三方购买；
- 企业管理员审批；
- DNS；
- 支付；
- 私有平台登录。

### High-risk irreversible action

例如：

- 删除生产数据库；
- 覆盖生产数据；
- force push 主分支；
- 删除大量用户文件；
- 修改生产服务器。

### License blocker

目标复用方式被许可证明确禁止且不存在合理替代。

除此之外默认自主继续。

---

# 7. 上下文持久化

长时间任务不得依赖聊天记忆。

关键状态写入：

```text
STATUS.md
```

至少保持：

- 当前 Phase / Milestone；
- 已完成；
- 正在进行；
- 下一步；
- Build/Test；
- 当前问题；
- 关键设计；
- 最近修改；
- branch / commit；
- blocker。

---

# 8. 上下文压缩前协议

判断上下文很长或会话即将结束时：

1. 立即更新 `STATUS.md`；
2. 更新 `PLAN.md`；
3. 更新 `ROADMAP.md`；
4. 记录关键 ADR；
5. 运行当前必要 Build/Test；
6. Git checkpoint；
7. 确认 git status；
8. 下一会话重新读取：
   - TASK；
   - AGENTS；
   - PLAN；
   - STATUS；
9. 从 STATUS 的 Next Action 继续。

不要重新规划整个项目。

---

# 9. 禁止重复劳动

每个任务前确认：

```text
Does it already exist?
Is it partially implemented?
Is there similar code?
Can it be reused?
Are there existing tests?
```

禁止因为没读懂代码而：

- 重复实现；
- 创建第二套架构；
- 无必要替换稳定模块；
- 新建重复组件。

---

# 10. Git Checkpoint

如果仓库使用 Git：

推荐：

```text
一个可独立验证阶段
=
一个 checkpoint
```

避免：

- 每几行一个 commit；
- 数小时所有内容一个巨大 commit。

Checkpoint 前：

- Build/Test 与阶段 DoD 对齐；
- STATUS 更新；
- PLAN 更新；
- 保护用户已有修改。

未经明确授权禁止：

```text
git reset --hard
git clean -fd
git checkout .
force push
```

---

# 11. 禁止伪实现

以下不是完成：

```text
TODO
FIXME
placeholder
NotImplemented
pass
fixed mock response
fake market data
demo hardcode
empty API
empty UI
unused schema
button no-op
backend without UI when TASK requires UI
frontend mock when TASK requires backend
```

---

# 12. 架构优先级

始终：

```text
reuse existing architecture
>
extend existing architecture
>
local refactor
>
new subsystem
```

只有当前 TASK 必须时才做重大重构。

---

# 13. 重构边界

允许：

1. 当前任务必须；
2. 明显影响可靠性；
3. 明显阻碍后续必需工作。

禁止：

- 纯审美；
- 全仓格式化；
- 无关技术栈替换；
- 只为“更优雅”重写大模块。

---

# 14. Phase 验收

每个 Phase：

```text
Code
↓
Build
↓
Unit Tests
↓
Integration Tests
↓
Necessary Live / Functional Test
↓
Review
```

只有必要项全部通过：

```text
Phase Completed
```

---

# 15. Final Acceptance

最终必须重新读取：

```text
TASK.md
```

逐项验证全部 MUST requirements。

然后执行完整：

- Backend Build；
- Frontend Build；
- Unit；
- Integration；
- E2E；
- live-source verification；
- PIT；
- traceability；
- i18n；
- theme；
- report review/version；
- scheduler/recovery；
- prediction validation；
- production deployment；
- backup/restore。

---

# 16. Final Reviewer Pass

完成实现后，切换 Reviewer 视角再次检查并直接修复：

- unfinished code；
- swallowed exception；
- missing error handling；
- null issues；
- concurrency；
- leak；
- security；
- injection；
- auth bypass；
- hard-coded secrets/config；
- duplicated system；
- API mismatch；
- frontend/backend contract；
- missing i18n；
- missing theme；
- XSS；
- unsafe external content；
- PIT violation；
- report traceability gap；
- prediction mutability；
- untested recovery。

不得只输出 Review Report 后结束。

发现问题必须修复并重新验证。

---

# 17. 不得提前结束

禁止：

```text
“基础框架已完成”
“剩余可以后续实现”
“这里给出示例”
“建议下一步”
“如果需要我可以继续”
```

只要仍属于 TASK：

> 直接继续执行下一步。

---

# 18. 时间不是停止理由

30 分钟、2 小时、8 小时都不是结束条件。

如果上下文/执行窗口有限：

```text
Persist State
→ Checkpoint
→ Resume
```

而不是降低目标。

---

# 19. 自主决策权限

普通工程决策自行决定：

- class/method name；
- small file structure；
- internal interface；
- test implementation；
- small dependency；
- bug fix；
- internal data representation。

决策优先：

```text
existing project conventions
>
consistency
>
mature engineering practice
>
minimum complexity
```

长期影响架构的决策写 ADR。

---

# 20. 最终输出

只有 TASK 完成后对用户输出简洁总结：

```text
## 完成情况
任务：完成

## 已实现
...

## 验证
Backend Build: PASS
Frontend Build: PASS
Unit Tests: PASS
Integration Tests: PASS
E2E: PASS

## Git
Last Commit: ...

## 已知非阻断问题
None
```

过程状态写入仓库文件，不用最终输出大量流水账。
